# Рекомендации Сергею / MyWorld

Первая рабочая версия: `/work/` — услуги и форма, `/r/CODE` — персональная ссылка, `/partners/` — кабинет владельца. Рекомендация относится к услугам Сергея, не к покупкам у Ильмиры. Проценты, бонусы, выплаты, договоры и каталог экспертов не реализуются. Для бота уведомлений подготовлена отключённая без токена очередь; автоворонки бота здесь нет.

## Карта сохранения

Исходные объекты главной доски, их координаты, фотографии, клиентские концепции и предыдущие маршруты сохранены. Добавлена отдельная заметка к заявке и подсказка о перетаскивании; `/#works` открывает область работ. Новая вертикальная страница использует оригинальные portrait.jpg, washi-world.png и локальные шрифты MyWorld, а работы показывает по кнопке на доске. Тексты объясняют клиентскую пользу, без выдуманных отзывов и результатов.

## Работа

Node.js 24 LTS, без дополнительных зависимостей. `node referral/server.mjs` — локальный сервер 4342. `node --test referral/test.mjs` — проверки. `DATA_DIR` задаёт закрытый каталог базы; по умолчанию `referral/.data`, он исключён из Git. `PUBLIC_ORIGIN` — точный HTTPS-домен в production; `PORT` — loopback-порт. `MEDIA_DIR` указывает каталог с `media/` и `fonts/` (локально `public`).

`node referral/operator.mjs setup` создаёт отдельный пароль владельца в приватном `owner-access.txt` и хеш scrypt; существующий доступ не перезаписывает. Файл не публиковать, не отправлять партнёрам. `node referral/operator.mjs partner ilmira "Ильмира"` создаёт её ссылку. Имя и код новых партнёров можно задавать в закрытом кабинете.

Переход по ссылке фиксирует первую действующую рекомендацию в подписанном HttpOnly cookie на 30 дней. Форма получает одночасовую подписанную сессию и CSRF. Подмена публичного параметра не может заменить подписанного рекомендателя. Заявка сохраняется в SQLite с версией согласия, временем и кодом партнёра. Повтор того же Telegram в течение суток не создаёт дубль и не заменяет первую рекомендацию. Если cookie удалён, устройство изменено или человек написал прямо в Telegram, автоматической атрибуции нет: в кабинете будет только фактически сохранённая заявка. Переходы не равны покупкам. Статусы «Новая», «Связались», «Оплачено», «Закрыта» отмечает владелец вручную, деньги не начисляются.

Публичные API не возвращают списки заявок, контакты и статистику партнёров. Владелец видит последние 500 заявок; полная база остаётся на сервере. Вход: сессия 8 часов, Secure/HttpOnly/SameSite cookie, пароль scrypt, ограничение попыток и серверная проверка Origin+CSRF. Ограничения отправки хранятся в SQLite и переживают рестарт. IP используется только в суточном HMAC для ограничения запросов. Nginx должен передавать X-Real-IP из $remote_addr, а не доверять клиентскому заголовку. В интерфейсе данные вставляются через textContent, не HTML.

## Развёртывание

Не применять к неизвестному серверу. Сначала проверить действующий MyWorld, Node, Nginx и службы. Создать независимую loopback-службу, системного пользователя без shell и закрытый DATA_DIR. Перед изменением сохранить текущий Nginx вне sites-enabled. Добавить только маршруты `/work/`, `/r/`, `/partners/`; не заменять `/`, `/manage/`, `/audit/` и клиентские сайты. Проверить `nginx -t`, затем reload. Настройка origin и HTTPS обязательна; без неё production не запускается.

После установки выполнить `operator.mjs setup` и `operator.mjs partner ilmira "Ильмира"` от системного пользователя `myworldref` с `DATA_DIR=/var/lib/myworld-referrals` и `PUBLIC_ORIGIN=https://space.lpsflow.ru`, не от root: приватные файлы должны быть доступны только владельцу службы. Доступ находится в `/var/lib/myworld-referrals/owner-access.txt`, его передают только Сергею.

Установщик включает ежедневный закрытый backup timer (04:20 по часовому поясу сервера). `deploy/backup.mjs` делает согласованную копию SQLite через VACUUM INTO вместе с secret и admin-password.json в `/var/backups/myworld-referrals`, не копирует активную SQLite без WAL. Восстановить один secret с базой, иначе cookies перестанут действовать. Архивы не удаляются автоматически; нужно контролировать свободное место. Это локальные копии на том же сервере, не внешнее резервирование. Внешняя копия и срок хранения заявок требуют отдельной настройки; не заявлены выполненными. До реальной установки ни таймер, ни production-backup не запущены.

Перед реальным приёмом обращений владелец должен подтвердить тексты, корректность контакта @lp_sergey и реквизиты/документы обработки данных. Короткое уведомление на странице описывает фактическое поведение и не выдаётся за юридическую проверку. Страница не принимает оплату.

## Граница проверки

### Заявки и Telegram (07.10.2026)

Форма занимает всю ширину секции. После подтверждённого сохранения откроется `https://t.me/lp_sergey?text=...` с черновиком из имени, контакта и описания; посетитель должен сам отправить сообщение. В успешном состоянии остаётся запасная ссылка. Поддержка параметра text описана в https://core.telegram.org/api/links#public-username-links; отдельные старые клиенты могут игнорировать черновик, сохранённая заявка от этого не теряется.

Таблица notifications записывается в одной транзакции с новой заявкой. Для уведомлений добавить TELEGRAM_BOT_TOKEN и TELEGRAM_OWNER_CHAT_ID в закрытый `/etc/myworld-referrals.env`, затем перезапустить службу. Секрет не должен попадать в Git, браузер или журналы. Владелец должен предварительно нажать Start в своём боте. Пока токена нет — отправки отключены, заявки и очередь сохраняются. Очередь повторяет неудачные попытки с задержкой до часа; доставка at-least-once, при неопределённом сетевом ответе возможно повторное уведомление. Не обещать гарантированную доставку или подключённого бота без проверки.

На основном сайте путь `/#works` открывает область работ; заметка «Сделаем ваш проект?» ведёт на `/work/`. В dev заметка направляет на отдельный локальный сервис 4342. Постоянная подсказка в области работ объясняет перетаскивание и масштаб.

Автотесты используют только синтетические данные и отдельную временную базу. Проверяется сохранение, первая рекомендация, подмена cookie, дубль, CSRF/Origin, валидация, приватность API, вход/выход владельца и изменение статуса. Проверка не является независимым аудитом безопасности. Локальный успех не доказывает публикацию: реальный домен и сервер проверяются отдельно после установки.
